# 2026-11-24 改动清单

起因：2026-11-23 在 captain 上用 Qwen3.8-27B 试跑（第 0 折，给法 1 和 2c，策略 v3，搜索和 ACE live）。5 次搜索里 3 次超时，结果全部作废；ACE 的 10 次任务全部失败，没有写出一条经验。

## 发现的问题

1. **超时直接作废**：搜索超时后，代码用 SIGKILL 杀掉 run_evolve.py，已完成迭代里的好策略一起丢掉。比如 2c 第 10 轮，第 5 次迭代已经评出 combined_score 1.175，整次搜索仍记为失败。
2. **残留进程**：subprocess 超时只杀主进程。OpenEvolve 的工作进程是 fork 出来的，继承了主进程"收到 SIGTERM 只请求停止"的处理函数，所以主进程死后它们会把手上已排队的迭代跑完，继续调用模型。evolve.log 里最后一两次评测之后，都没有主进程的 "Iteration … completed" 记录，2c 第 10 轮评出 1.313 的那次也是这样，结果没人接收。跑完后这些进程很可能一直挂着占内存。
3. **ACE 调用必然超时**：`team_ace/backend.py` 把每次调用的超时写死为 20 秒、不重试，输出上限 1024 token。Qwen3.8-27B 一次回答要几十秒到几分钟，所以每个 worker 都正好在 21.5 秒失败。
4. **ACE 状态跨运行共用**：team_ace 只按数据和检查点划分分区，在相同的折和给法上重跑会重新打开上次的分区，接着用它已经花掉的调用额度、旧队列和旧经验。同一次运行里两个策略上线同一个模型时也会共用分区。
5. **报告看不出搜索是否成功**：只有"搜索请求"一列，只能用训练次数倒推。

## 修改

| 路径 | 内容 |
|---|---|
| `team_sim/search.py` | 搜索在独立进程组里运行（`run_in_group`）。到时限先发 SIGTERM，OpenEvolve 保存已完成迭代里最好的策略后正常退出；90 秒内没退出才强杀。结束后清掉组里所有残留进程。默认时限从 3600 秒改为 1800 秒。最佳策略和起点策略相同时不当作新候选。新增 ACE 单次调用超时和 token 上限，并检查 worker 时长够不够。ACE 状态改放在 `state/sim/<输出目录名>-<路径哈希>/f<折>-p<给法>-<策略>/` 下 |
| `team_sim/__main__.py` | 新参数 `--ace-request-timeout`（默认 300）、`--ace-max-tokens`（默认 4096）；`--search-timeout` 默认改为 1800；参数不合法时直接报错退出 |
| `team_sim/decide.py` | 每轮决策记录 `search`（退出码、是否到时限、耗时、有没有最佳策略、是否和起点相同） |
| `team_sim/run.py` | summary 增加 `search_adopted`、`search_time_limited` |
| `team_sim/report.py` | report.md 增加"搜出新候选 / 搜索候选上线 / 搜索到时限"三列；旧 summary 缺字段时显示"—" |
| `team_ace/backend.py` | **已有代码，改动最小**：单次调用超时和 token 上限改为从 `ace.request_timeout_s` / `ace.max_tokens` 读取，**默认仍是 20 秒和 1024**，原有 A/B/C 运行行为不变；去掉回复开头的 `<think>…</think>` 块 |
| `tests/test_team_sim.py` | 新增 7 个测试：到时限正常停止并清掉残留进程、无响应时强杀、正常结束不受影响、ACE worker 时长检查、ACE 状态按运行和策略分开、backend 默认值不变和覆盖值检查、旧 summary 生成报告 |
| `docs/SIMULATOR.md` | 第 5、6 节补充上述内容 |

## 验证（本机，NumPy 1.26.4）

- `HARNESS_DATA_A/B/C=... python -m unittest discover -s tests`：127 个测试全部通过（原 120 个 + 新增 7 个）。
- 真实 OpenEvolve 加一个每次回复延迟 15 秒的假模型服务器，时限设 45 秒：两次搜索都在时限收到 SIGTERM，日志依次出现 "Shutdown requested"、"Saved best program"，退出码 0。搜到的策略进入验收门，第 1 轮被采用上线。运行结束 20 秒后没有残留的 run_evolve 进程。
- 同样设置连跑两次（ACE fixture 模式）：两次运行的 ACE 状态分别在各自目录下，不再出现 "model-call budget exhausted"；第 2 轮能带入上一轮写出的经验（carried 1）。
