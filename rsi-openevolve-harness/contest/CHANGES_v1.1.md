# 比赛镜像 v1.1 改动说明（2026-11-27）

镜像标签 `zhixun-rsi:v1.1`；导入：`docker load -i zhixun-rsi-v1.1.tar`（或直接用 `.tar.xz`）。校验值见 `SHA256SUMS`。

## 改了什么
把经验卡 `A-00-BASE-CLASSMIX-01` 编译成了候选策略。这张卡由原来的 `A-00-BASE-GASMIX-01`（只针对乙醛/乙醇）通用化改写而来。新候选和原有候选一样，都要过验收门才能上线。

1. **类别加权**（只用于分类任务，也就是 A）：每一类在损失里的总份量相同，样本少的类不会被多数类淹没。权重只用训练集统计，不碰验证集。新增两个候选：
   - `balanced`：官方续训 + 类别加权；
   - `pick+balanced`：选轮 + 类别加权。
2. **新数据加权**（A/B/C 都用）：
   - 每轮把训练集样本 id 的哈希记进 `/state`；下一轮里没出现过的样本，就是新样本。
   - 另写一份训练文件，新样本每条按 3 条计（多复制 2 份，副本 id 加后缀 `#recent1`、`#recent2`）。
   - 新增候选：A 是 `recent+balanced`，B/C 是 `recent+pick`。
   - 第 1 轮、本轮全是新样本、没有新样本，或训练文件会超过 120 MiB 时，不训练这类候选。
3. **每轮记录数据情况**：训练行数、新样本数、验证行数；回归任务还记录训练标签均值和新样本标签均值。这些信息写在 stderr 日志 `rows train N (new M) validation V` 里，也写进每轮记录的 `configuration.data`。用这些数字可以看出平台每轮是怎么给数据的。

其他不变：验收门（P ≥ 0.90 且护栏不破）、静态基线回滚、每轮 1 次 Qwen 审阅（只能否决）。

## 测试
- 适配器测试 7 个全部通过，是用从镜像里解出的 `/app` 跑的。内容包括：
  - describe、A/B/C 各一整轮、否决保留父模型、predict；
  - 两轮新数据测试：第 2 轮在第 1 批之外加入一半验证数据作为新数据，A 正确认出 622 条新样本，并选中 `recent+balanced`；B 认出 839 条，训练了 `recent+pick`，但截断更好，选的是截断；
  - 辅助函数的单元测试。
- 第 1 轮的选择和 v1 相同：A 选官方续训，B 选截断，C 选选轮。A 新增的加权候选也过了验收门，但分数略低，没被选上。
- 仓库全部 144 个测试通过（含 team_gas 用新卡的测试）。镜像中没有密钥、数据或权重。

## 跑完要看什么
- stderr 里每轮的 `rows train … (new …) validation …`：看平台每轮给多少新数据、是不是累积着给。
- 每轮记录的 `configuration.choice`：新候选有没有被选上。
- `reason` 里 Qwen 是同意还是否决、否决了几次。
