# 比赛镜像 v1.3 改动说明（2026-11-28）

镜像标签 `zhixun-rsi:v1.3`。直接上传 `zhixun-rsi-v1.3.tar`：193,320,960 字节，Windows 资源管理器显示 188,790 KB，SHA256 见 `SHA256SUMS`。

## 改了什么（只对 C，A 和 B 与 v1.2.1 相同）
C 改用队友的"有限动作智能体"（`C_agent_delivery_20261127` 的 `agent/` 代码原样放在 `/app/c_agent`）。每轮的流程：
1. 把本轮公开验证集按分组切成两半，一半是**挑选集**，一半是**验收集**。
2. 从平台给的父模型出发，跑一次官方续训，作为参照。
3. 最多 3 步：每步 Qwen 读挑选集上的诊断（两端偏差、FD 分组、NASA）和经验卡，从 12 个固定动作里选一个；控制器训练这个动作，只有在挑选集上更好、而且护栏不破时才保留。
4. 最后在验收集上把"最好方案"和父模型、官方续训比较（队友自己的验收门），通过才上线，否则保留父模型。
5. 经验库放在 `/state`，跨轮保留；第一轮从队友验证过的一张种子卡开始。

## 接入时做的适配（队友的 `agent/*.py` 一行没改，适配都在 `contest_submission.py` 里）
- **模型调用**：队友的代码用自己的 PyTRiO 客户端和密钥。镜像里换成走平台的 `rnd.model()`，参数相同（关闭思考、JSON 模式、最多 600 token、温度 0.25），镜像里没有任何密钥。
- **训练超时**：队友配置里每次训练限 20 秒（在队里服务器上测的），平台 CPU 速度未知，放宽到 600 秒。
- **数据切分**：每轮按本轮验证集重新切分，不用初始的固定清单（队友文档要求）。
- **验收**：直接调用队友的 `gate_choice`，去掉了本地用的"冻结文件"校验流程。
- **兜底**：智能体出任何错，本轮退回 v1.1 的候选做法，整次运行不会因此失败。
- **调用次数**：C 每轮 1～3 次 Qwen 调用（v1.2.1 是 1 次），10 轮最多 30 次。

## 测试
用从镜像解出的 `/app` 跑适配器测试，13 个全部通过。新增 3 个 C 测试：
- 单轮：3 步依次是 `pick_best_epoch`（挑选集 RMSE 47.5576，保留）、`tail_error_1_1`（47.7583，没有明显改进）、`keep`。验收集上父模型 56.89，官方续训 56.40，候选 56.17，上线候选。挑选集上的数字和队友 RESULTS.txt 里的一致，说明接入没有改变队友的实验。
- Qwen 回复不是合法动作：3 步都记为无效回复，本轮照常走验收门结束。
- 两轮：经验库跨轮保留，没有报错。

本机每轮 C 约 35～40 秒。

## 风险
- 智能体在整个挑选集上优化，没有"新样本加重"。C 在第 4、7、9 轮来的新数据只占验证集约 1%～3%，按第一次试运行的推算，其中第 9 轮那批明显更难（老模型 RMSE 72，老样本约 51.5）。这一点智能体照顾不到。
- 验收集每轮都是同一批老样本加上新样本，10 轮反复在上面挑，会有一定的选择偏差（v1.1 也有同样的问题）。
- 平台上每轮 C 会多训练几次、多调用几次 Qwen，资源分会略降。
